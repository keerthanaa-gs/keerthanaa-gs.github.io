Case study

// from "someone complained" to shipped automation
Enterprise integration · Financial services · Fieldproxy

Moving sensitive data without a human in the middle

The complaint

A financial services client needed sensitive data flowing into our platform regularly. The existing way was manual — files prepared and uploaded by hand — which for a regulated company meant every transfer was a security question waiting to be asked.

Mapping the real process

I walked their actual flow, not the assumed one: where data originates, who touches it, what happens when a file is malformed, what security needed to sign off. The real requirement wasn't "upload files" — it was "move sensitive data on a schedule without a human being the risk."

Worth solving?

Recurring, not one-time — every manual cycle cost effort and carried risk, and it blocked the account from scaling. The harder call was scope: what we commit to now versus later.

The handoff

A spec for automated encrypted ingestion (AES-256), covering the format contract, encryption approach, and how malformed data fails loudly instead of silently. Two explicit lists went to both engineering and the client: confirmed capabilities vs. feasibility-check items — so nobody built, or was promised, something unvalidated.

The lesson that stuck: clients don't buy features. They buy confidence that someone owns the outcome — and that confidence is built in the gap between "confirmed" and "we're still checking."

How I work

// opinions formed by shipping, not reading

01PM is not PRD generation

Anyone can generate a spec with AI now. The job is what's around it: understanding users, making trade-offs, and owning whether the outcome actually happened.

02Confirmed ≠ probably

Every enterprise project I've run stays alive on one discipline: never letting "what we've confirmed" blur into "what we're still validating" — with clients or with engineering.

03Build with AI, verify like it's client data

I use Claude Code and Cursor daily. AI output gets the same distrust as a legacy data export: guards, validation, review. "Usually correct" is a failure mode in production.

04Adoption is the only compliment

Kind feedback is noise. The signal is whether people come back tomorrow without being asked — and complain when it's missing.
